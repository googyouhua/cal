# 名单导入与成绩回填

- 日期：2026-11-19
- 修订：2026-11-22（列映射、按学号保留/清空两种导入方式，对齐当前自动确认/自动等号/结果后暂停/语音）
- 状态：待批准
- 范围：`index.html`（单文件计算器）与 `tests/`（Playwright 场景）；不改语音引擎与语音资源
- 规模：项目（新数据模型 + 列映射 + 导入合并 + 导出 + 名单表 + 编辑 + 测试）

**本轮方向（对话中拍板，或我提出后未反对）**：结果后暂停保留；导入方式 C（保留同学号成绩 / 清空重录）；学号、姓名、成绩、序号四列都由用户在预览里选；只按学号合并，重复学号禁用合并；文件里的成绩值不采用；语音 v1 只念结果；自动按等号算一次成功回填；导入对话框停自动确认并屏蔽物理键盘；编辑草稿浮动到行旁；名单模式用“保存并完成/取消”，无名单模式仍是“关闭”；手机上一律两行卡片。

**本轮建议（批准文档即采纳，觉得多余可在批准前删）**：加“粘贴名单”入口；坏数据时显示“无法读取”提示；不做名单级“撤回上一位成绩”。

## 1. 为什么做

这个计算器现在用于**统分**：一份成绩由若干笔分组成，按“=”算出一个总分。但名单在 Excel 里，成绩在页面历史里，两边是断开的：算完一个人要手抄回表格；改了一个人的历史，表格不会跟着变。

目标：导入一份带顺序的名单，按名单顺序连续统分；每个成功计算自动落到下一位头上；编辑某人的成绩就改那一行；随时导出一份能直接交的 CSV；名单改错时可以只改名字、不丢已录成绩。

用户故事：

1. 我有一份 50 人的名单。导入后从第 1 位开始录，每算完一个人自动记到他的名字后面并跳到下一位。录到第 20 位发现第 3 位算错了，点第 3 行的编辑改掉，导出时第 3 行就是新成绩。中途手机锁屏、刷新，已录的不会丢。
2. 录到第 20 位，名单里第 5 个名字写错了。我改好 CSV 重新导入，选“保留同学号成绩”；前 20 条还在，名字和顺序按新文件更新。
3. 换班或换一份新名单：选“清空重录”，从第 1 位开始，旧成绩不混进来。

## 2. 已定行为

### 2.1 导入名单

#### 2.1.1 文件、编码与解析

- **只做 CSV**。`.xlsx` 浏览器读不了；要么打包解析库（违背单文件无依赖），要么自己解 zip + XML（共享字符串、多工作表、日期格式都要自己兜，手机上难排错）。导入面板给“下载样例名单”，文案写“Excel 里选‘另存为 → CSV UTF-8（逗号分隔）’”。
- **编码**：兼容 UTF-8（带/不带 BOM）与 GBK。先按 UTF-8 解码；结果含替换字符 `U+FFFD` 时改用 GBK 重解；仍失败或含 NUL 则报错。BOM 去掉。
- **分隔符**：逗号、分号、制表符自动识别；在表头记录里忽略引号内的分隔符，取出现次数最多的一个；并列按 `,` → `;` → `\t` 优先。
- **CSV 语法**：RFC 4180。引号内的分隔符/换行合法，`""` 表示一个引号；支持 LF、CRLF、孤立 CR。单元格去首尾空白；引号内的换行保留。
- **表头**：第一行固定是表头，也按 RFC 4180 解析；表头全空则拒绝。
- **数据行**：按表头列数对齐；少补空，多出的单元格忽略；空行跳过。
- **文件里的成绩值不采用**：导入永远从空成绩开始；选“保留”时保留的是本机已录成绩，不是文件里的成绩（见 2.1.3）。
- **拒绝**：0 字节 / 只有空行 / 表头全空 / 解码失败 / 含二进制 NUL。拒绝时对话框显示原因，当前名单、成绩、计算器状态不变，可重新选择。
- **首行是数据而非表头**：首行会被当表头丢掉；预览的人数和前 3 行会暴露；文案提示“第一行会当作表头”。映射后 0 人时确认禁用，不会导入空名单。
- **两个入口**：`选择文件` 与 `粘贴名单`。粘贴文本已经解码，走同一套分隔符/CSV/列映射/预览逻辑；文件名用 `粘贴名单`。

#### 2.1.2 列映射

预览页固定显示四个下拉（不是自动识别后就锁死）：

| 角色 | 下拉 | 默认 |
| --- | --- | --- |
| 学号 | `学号列` | 别名 `学号 / 考号 / 学籍号` 的最左列；没有则 `无` |
| 姓名 | `姓名列` | 别名 `姓名 / 名字 / 学生姓名` 的最左列；没有则 `无` |
| 成绩 | `成绩列` | 别名 `成绩 / 分数 / 得分` 的最左列；没有则 `无` |
| 序号 | `序号列` | 别名 `序号` 的最左列；没有则 `无` |

- 每个下拉的选项 = 表头每一列（带列号，如 `第 2 列：学号`，重名也能区分）+ `无`。
- 学号/姓名不能是同一列；四个角色两两不能重叠。下拉里排除已被其他角色选中的列。
- 学号和姓名至少选一个；两个都 `无` 时确认按钮禁用，提示“请指定姓名或学号列”。
- 学号列决定合并键；选 `无` 时只能清空重录（见 2.1.3）。
- 成绩列/序号列只决定导出写在哪一列；选 `无` 时导出在末尾补 `成绩` / 最前补 `序号`。
- 映射改变时，预览前 3 行、人数、可保留/丢弃/新增数量、`保留列` 标签全部重算。
- 表头别名只用于默认值，不是硬规则；用户可把任意列指定为任意角色。
- 表头匹配去首尾空白；导出保留原表头文本。
- 行跳过：所选「学号」和「姓名」都为空的行跳过；`seq` 在跳过之后按 1..N 生成。
- 预览显示：`识别到 N 人`、四个下拉、列标签（每列显示角色或 `保留：<表头>`）、前 3 行（序号/学号/姓名/成绩 `—`）、导入方式、警告、按钮。
- 映射只作用于本次导入；确认时写成 `roles` 存进名单（见 2.5），导出按 `roles` 写回，不再靠表头别名猜。
- `roles` 与 `headers` 一一对应，取值 `seq | id | name | score | extra`；每个角色至多一个；其余是 `extra`。`rows[i].extra` 按 `extra` 列顺序存值。

#### 2.1.3 导入方式：清空 / 保留同学号成绩

仅当本机已有名单且有至少 1 条已录成绩时出现“导入方式”单选；否则不出现，直接开始录入。

- `保留同学号成绩（K 条）`（可保留时默认）
- `清空重录（M 条）`（M = 当前已录成绩数）

**匹配规则**

- 只认所选「学号」列；按去首尾空白后的原字符串精确匹配。不按姓名、不按行号、不看「序号」。
- 学号为空的行不参与匹配；新行从空开始。
- 任一侧出现重复的非空学号 → 禁用“保留”，只能清空重录，并在提示里列出重复的学号（最多 3 个）。重复学号仍可导入并录入，只是不能合并。
  - 判定是**宽**的：只要任意两个非空学号相同就禁用，不管其中一行有没有成绩、也不管它会不会参与匹配。理由：重复学号本身是数据错误，先让用户修正或清空，避免替他挑一条做隐式选择。
  - 禁用时：预览不显示 K/D/A（没有可信匹配），改为显示“无法按学号保留：学号 … 重复”；导入方式区只保留“清空重录”（选中），不渲染“保留”单选项；`data-mode="clear"`，主按钮“清空并开始录入”。
- 未指定学号列、或没有匹配到任何同学号成绩（K = 0）→ 只提供清空重录，并说明原因；同样不显示 K/D/A、不渲染保留单选项。
- 改名不影响保留：学号相同就保留成绩；姓名、班级、顺序、表头以新文件为准。
- 旧名单里被删掉的学生，成绩随旧行丢弃；新名单里新增的学生从空开始。
- 保留的成绩只把 `entry.seq` 改成新行号；`operator / operands / base / expression / result` 原样带过去。
- 文件里的成绩值不采用；保留的是本机 `entry`。预览的 3 行成绩显示 `—`。
- 可保留时，预览给出：可保留 K 条、旧成绩将丢弃 D 条、新增 A 人（A = 新名单里本机没有的同学号；其余新行空着）。K + D = 当前已录成绩数。
- 选清空：新名单全部 `entry = null`；当前成绩全部删除。
- 选保留：新名单按新顺序/姓名/表头重建，同学号的行带上旧 `entry`；不匹配的旧成绩丢弃。
- 两种方式都：清空计算历史、丢弃编辑草稿、计算器归零回 `select`、写本机存储、按新顺序定位下一位（第一个空成绩行；清空时就是第 1 位）。
- 主按钮随选择：`保留成绩并开始录入` / `清空并开始录入` / 无成绩时 `开始录入`。
- “清空”选中时警告用警示色；保留选中时只显示匹配/丢弃/新增数量，不用红色。
- **改映射后**：若当前选择是“保留”但保留已不可用，自动切到“清空”；若保留仍可用，保持当前选择；若当前是“清空”，不自动切回“保留”。
- **重新选择文件**：重新解析后按新文件的默认可保留性选择（能保留则默认保留，否则清空）。

#### 2.1.4 对话框与确认

一个原生 `<dialog>`，三段式：

1. **入口**：格式说明、`选择文件`、`粘贴名单`、`下载样例名单`、`取消`。
2. **粘贴**（仅点“粘贴名单”）：一个 textarea + `解析` + `返回` + `取消`；空文本报错；解析成功进入预览。
3. **预览**：`识别到 N 人`、列映射四个下拉、列标签、前 3 行、导入方式、警告、`保留成绩并开始录入` / `清空并开始录入` / `开始录入`、`重新选择`、`取消`。

- 点确认才真正替换名单；取消、Esc、关闭对话框都不改名单/成绩/计算器。
- 打开对话框时 `stopAutoConfirm()`；关闭后若主输入框非空则重新计时。确认后输入框已清空，不会重新计时。
- 对话框打开期间，自动确认的 guard 也返回 false；物理键盘的 keydown 处理遇到任何打开的 `<dialog>` 直接 return；数字/回车/等号不会在背后改计算器。
- 确认时归零：停止自动确认、清除结果后暂停、丢弃未播放的按键/结果语音任务（正在播的句子可播完）、清空编辑草稿与快照、运算符回到未选、操作数/算式/结果清空、主输入框清空、回到 `select`、`history = []`。
- 确认后焦点回到“导入”按钮；状态行显示导入结果。回填/导入不自动滚动名单，下一位提示常驻。
- 解析失败（0 字节、只有空行、表头全空、解码失败）时，对话框显示原因，停在入口/预览，可重新选择；当前状态不变。
- 映射未完成（学号/姓名都 `无`）或映射后 0 人时不是解析失败：确认禁用 + 提示，用户可改映射；不写 `data-error`。
- `dialog` 带 `data-error="true"` 表示解析失败；`data-mode="keep|clear"` 只在导入方式区出现时存在，否则没有该属性；`data-count` / `data-keep-count` / `data-drop-count` / `data-new-count` 供测试读取（后三个只在保留可用时存在）。
- 导入方式区：本机有 ≥1 条成绩时出现；清空单选项始终出现；保留单选项只在可保留时出现（否则不渲染）；没有成绩时整个区不出现。
- 焦点进入对话框内的可见控件；Esc 可关；关闭后回到打开它的按钮（`导入` 或 `导入名单`）。

#### 2.1.5 清除名单

- 工具条“清除”，二次确认（原生 `confirm()` 或页内确认）：`清除后本机保存的名单和 N 条成绩都会删除。`
- 确认后：删除 `cal-phone.roster.v1`、名单/成绩清空、计算历史清空、计算器归零回 `select`、回到无名单模式。
- 删除失败（localStorage 抛错）：内存清空并显示“本机存储不可用…”提示；不保证刷新后仍为空。
- 取消：不做任何改动。

### 2.2 名单表

导入成功后，原来的“计算历史”区变成“名单成绩”区：

- 标题行：`名单成绩` + 文件名（没有文件名用 `名单`）；工具条 `导入` / `导出` / `清除`。
- 无名单时：标题 `计算历史`、注 `仅当前页面`、工具条只有 `导入名单`；`导出` / `清除` 隐藏。
- 摘要行：`N 人 · 已录 K · 下一位 3 李四`；没有姓名显示学号；两者都没有显示 `第 3 位`；录满显示 `N 人 · 已录 N · 名单已录满`。
- 计算器输入框下方常驻一行小字：`下一位 3 李四 · 按 = 记入成绩`；录满：`名单已录满；按 = 只计算结果，不再写入名单`。无名单时不出现。
- 每一行是一张两行卡片（手机上一律卡片，不做 5 列表格）：
  - 第一行：`序号`、`姓名`（或 `第 N 位`）、`学号`（有才显示）、`编辑中` / `下一位` 标签。
  - 第二行：已录 → 完整算式 + 成绩（`formatValue`）+ `编辑`；未录 → 成绩 `—`，没有算式、没有编辑按钮。
- 列表按名单顺序升序；最新录入出现在下方，不回顶部。
- 下一行（`seq` 最小的空成绩行）行底色高亮 + `下一位` 文字标签；编辑态时被编辑行加 `编辑中` 高亮，下一行的描边/徽标弱化（但仍可见）。
- 列表随页面滚动，不做内部滚动区；50 人不会把计算器挤出屏幕（计算器始终在上方）。
- 长姓名/长学号单行省略，不换行撑破布局；320px 下第一行/第二行可换行但不横向溢出。
- 行内 `编辑` 的 `aria-label`：`编辑第 3 位 李四 的成绩`。
- 名单表用列表语义（`role="list"` + 每行 `role="listitem"`）；`下一位` 不能只靠颜色。
- 从下方行点“编辑”时，编辑草稿浮到视口底部（见 2.4），被编辑行滚到草稿上方；保存/取消后草稿回到原位，被编辑行滚入视野，焦点回到该行编辑按钮。

### 2.3 计算与回填

- 按 `=` 且计算成功（有限结果）时：
  - 名单模式、未编辑：写 `seq` 最小的空成绩行；该行变已录；下一位后移。
  - 名单模式、编辑态：原地覆盖被编辑行（见 2.4），不消耗下一位。
  - 名单已录满：结果照常显示，不写名单、不新增行；状态行 `名单已录满（N 人）；结果 X 未写入，如需修改请点行内编辑`。
  - 除零、非法输入、没有操作数的 `=`：不写名单、不消耗下一位，沿用现有错误/空操作行为。
- **自动按等号**（满 N 笔自动 `=`）算一次成功计算：照常回填并推进；基数不计入 N（现有）。
- **自动确认**（停顿后收数字）沿用；收下的一笔可能触发自动等号，随后可能回填。名单模式不改变这条链。
- **结果后暂停**（默认 1 秒）保留：名单模式也遵守；暂停期间数字键不生效，`appendCharacter` 直接返回；0 关闭；选运算符会清除暂停（现有）。状态行已显示“已记录…”，用户能感知。50 人默认每人多约 1 秒；想快就把设置改成 0。
- 写入记录与现有历史条目同构，并带 `seq`：
  `{ seq, operator, operands: [{value, display}], base: null | {value, display}, expression, result }`
- **基数**：沿用现有；每条记录保存自己的基数快照；名单行/导出只显示/写 `result`；编辑用该记录的 `base` 重算。
- **退格撤回**：沿用现有，只撤回当前输入/草稿里的操作数，不撤回已回填的名单行；误录用行内编辑改。
- **结果播报**：沿用现有，只念数字（如 `三十七点七`），不念姓名/序号/下一位；除零念 `不能除以零`；自动等号同样播。
- **震动**：沿用现有，只作用于屏幕计算键；名单工具条/编辑按钮不额外震动。
- 状态行：
  - 新回填：`已记录 3 李四：37.7；下一位 4 王五` / `已记录 …；名单已录满`
  - 编辑保存：`已更新 3 李四：37.7；下一位 4 王五` / `…；名单已录满`
  - 录满：`名单已录满（50 人）；结果 2 未写入，如需修改请点行内编辑`
  - 导入保留：`已导入；保留 K 条成绩；下一位 3 李四` / `…；名单已录满`
  - 导入清空：`已导入；从第 1 位 张三 开始`
  - 恢复：`名单已恢复；下一位 3 李四` / `…；名单已录满`
- 名单模式下不渲染 `history-item`；名单行是唯一成绩真值。无名单模式的历史行为完全不变。

### 2.4 编辑与同步

名单模式下，点某条已录入行的“编辑”：

- 复用现有编辑草稿（运算符、操作数 chip、基数标记、点选替换、换运算符、删除、追加）。
- 编辑态顶部/草稿标题：`正在编辑 3 李四`；状态行：`正在编辑 3 李四 的成绩`。
- 草稿按钮：`保存并完成`（主，等同 `=`）+ `取消`（次）。无名单模式仍是现有 `关闭`，不显示 `保存并完成`。
- 草稿提示：`改好数字后按「保存并完成」或 =；取消会放弃本次修改。`
- 点“编辑”时草稿浮到视口底部（`position: fixed`，左右 10px、`max-height: calc(100dvh - 20px)`、内部滚动、`z-index` 高于名单），页面加底部 padding；被编辑行滚到草稿上方。保存/取消后草稿回到计算器面板原位，移除 padding，被编辑行滚入视野，焦点回到该行编辑按钮。
- 按 `保存并完成` 或 `=` 重算成功后，原地替换那一行：
  - 序号、姓名、学号、行位置、总行数不变；
  - 成绩、算式、运算符、操作数、基数快照一起更新；
  - 不消耗下一位，不新增行；下一位指针不变；
  - 立即写本机存储；结果播报照常；结果后暂停照常。
- 点“取消”或关闭编辑：丢弃草稿，行内容不变（沿用现有快照恢复）；焦点回到该行编辑按钮。
- **编辑中再点另一行（或本行）的“编辑”**：不静默切换。保持当前目标和草稿不变，状态行提示 `先保存或取消当前编辑`；点击不改变状态。先保存/取消后，再点另一行正常进入。无名单模式保持现有行为（重定向到新记录，复用同一快照），不改。
- 编辑态出现空值/非数字/除零：沿用现有 no-op/错误态，那一行保持原样；不写存储。
- 编辑草稿不持久化；刷新回到已保存成绩。
- 下一位与编辑：下一行是空成绩行，不能编辑；编辑已录行不影响下一位。
- 无名单模式：编辑后仍追加一条新记录、原记录保留；草稿仍是 `关闭`；旧测试不动。

### 2.5 持久化

- 存储键：`cal-phone.roster.v1`。
- 值：

```json
{
  "version": 1,
  "fileName": "高一3班.csv",
  "headers": ["序号", "编号", "学生", "总分", "班级"],
  "roles": ["seq", "id", "name", "score", "extra"],
  "rows": [
    { "seq": 1, "id": "20230101", "name": "张三", "extra": ["高一3班"], "entry": null },
    {
      "seq": 2,
      "id": "20230102",
      "name": "李四",
      "extra": ["高一3班"],
      "entry": {
        "seq": 2,
        "operator": "+",
        "operands": [{ "value": 12, "display": "12" }, { "value": 30, "display": "30" }],
        "base": null,
        "expression": "12 + 30",
        "result": 42
      }
    }
  ]
}
```

- `headers` / `roles` 一一对应；`roles` 取值 `seq | id | name | score | extra`；每个角色至多一个；`rows[i].extra` 按 `extra` 列顺序。
- `entry` 为 `null` 表示未录入；否则带 `seq`、运算符、操作数、基数快照、算式、结果。
- 每次改变名单/成绩后立即写入：导入、成功 `=`、编辑成功、清除（删除键）。
- 页面启动读取：恢复名单/成绩/顺序/`roles`/下一位；计算器回到 `select`；状态行 `名单已恢复；…`；不恢复上次算式。
- `localStorage` 不可用或写入失败：页面继续以内存方式工作；名单区显示不可关闭提示 `本机存储不可用，刷新会丢失成绩。`；不抛错、不阻断录入。
- 读取失败/坏 JSON/未知 version/缺 `roles`/角色非法/行数据不合法：忽略这份存储，回到无名单模式，不覆盖原值；显示不可关闭提示 `本机名单数据无法读取，已忽略；原数据未覆盖。`
- 清除名单删除该键；无名单模式的历史仍只存当前页面（刷新清空），不写任何历史存储。
- 设置仍用 `cal-phone.settings.v1`，与名单互不影响。
- 存储写入逐次即可（50 行规模），不做节流；实现者可加。

### 2.6 导出

- 工具条 `导出` 在名单模式随时可用（未录完也能导）；无名单模式不显示。
- 生成 CSV：UTF-8 **带 BOM**，逗号分隔，CRLF，RFC 4180 转义。
- 列 = `headers` 原顺序；按 `roles` 写：
  - `seq` → `row.seq`（1..N）
  - `id` → `row.id`
  - `name` → `row.name`
  - `score` → 已录 `formatValue(entry.result)`，未录 `""`
  - `extra` → `row.extra` 对应值
- 没有 `seq` 角色：最前面补一列 `序号`；没有 `score` 角色：末尾补一列 `成绩`。有角色时写回原列（原文件里的同名旧值被覆盖）。
- 文件里的成绩列若映射为 `score`，导出写本机成绩；未映射则原样保留该列，另补 `成绩`。
- 文件名：`<fileName 去扩展名>-成绩-YYYYMMDD.csv`；`fileName` 为空用 `名单`；非法字符 `[\\/:*?"<>|]` 替换为 `_`；`YYYYMMDD` 用本地日期。
- 下载 `Blob` + `<a download>`；`file://` 可用；失败时状态行提示，不改页面/存储。
- 导出后状态行 `已导出 N 人（M 条成绩）`；不改页面、名单、存储。
- 编辑草稿未保存时，导出用该行原成绩（草稿不是成绩）。
- 导出文件**不能当存档恢复**：重新导入时文件里的成绩值不采用；本机成绩靠 `localStorage`。这是有意取舍（见 §5）。

### 2.7 无名单模式（保持现状）

没有导入过名单、或清除了名单时：

- 计算历史最新在上，刷新清空，不写存储；历史条目没有序号。
- 编辑后追加新记录、原记录保留；草稿按钮仍是 `关闭`，没有 `保存并完成`。
- 导入入口在“计算历史”标题旁（`导入名单`）。
- 名单区、下一位提示、导出/清除按钮都不出现。
- 设置、自动确认、自动等号、结果后暂停、基数、震动、语音完全不变。

### 2.8 布局与可达性

- 单文件、无外部依赖、无网络请求（语音资源是既有可选资源）；`file://` 直接打开可用（语音在 `file://` 下禁用，现有行为）。
- 320×568 与 390×844：导入入口/粘贴、预览（四个下拉、列标签、前 3 行、导入方式）、3 行/50 行名单、编辑浮动草稿、下一位标记，均无横向溢出。
- 可见交互控件宽高 ≥44×44 CSS px；输入字号 ≥16px；名单行正文 ≥13px。
- 名单表用列表语义；每行编辑按钮 `aria-label` 含序号与姓名；`下一位` 有文字。
- 导入对话框是原生 `<dialog>`，Esc 可关，焦点进入可见控件，关闭后回到打开按钮；四个下拉有 label；导入方式是 `fieldset/legend` + 单选；`data-error` / `aria-live` 同步。
- 320px 下四个下拉纵向排列；390px 可两列；列标签换行；对话框内容超高时内部滚动。
- 浮动草稿：左右 10px、底部安全区、`max-height: calc(100dvh - 20px)`、内部滚动；页面底部 padding 防止最后一行被盖住；软键盘弹出时随 visual viewport 收缩。
- 存储提示/坏数据提示可见，不只靠颜色；导入错误 `role="alert"`。
- 名单工具条在 320px 下可换行；导入/导出/清除都 ≥44px。

- 不做一人多条成绩或累计；一人一条。

- 不做按姓名合并；只按学号；没有学号或学号重复时只能清空重录。
- 不做“第一行是数据”的自动识别；第一行固定当表头，文案提示。
- 不做成绩小数位设置、四舍五入、百分制换算。
- 不做自动导出、自动下载、导出到原文件路径。

- 不改自动确认、自动按等号、基数、结果后暂停、退格撤回、除法错误、震动、语音的既有语义。

- 页面引用任何外部 http(s) 资源，或引入构建步骤/依赖。

## 5. 方案与取舍

**名单与历史的摆法**

- **A（已选）名单就是历史表**：只有一份数据，不存在“名单/历史谁是真值”；一眼看到进度；代价是最新录入在下方，需要常驻“下一位”提示。
- B 名单面板 + 现有历史并存：同一成绩显示两遍，两份数据要同步，最容易“改了历史名单没变”，弃用。
- C 只提示“下一位”：看不到谁没录，弃用。

**导入语义**

- A 一律清空：简单，但改一个名字也要重录。
- B 一律按学号合并：改名单不丢成绩，但换班/新名单时容易把旧成绩带进来，且没有“清空”逃生口。
- **C（已选）预览时让用户选“保留同学号成绩 / 清空重录”**：默认保留（安全），破坏性操作显式选择；代价是多一个决定和一套测试。用户故事 2 需要它。

**合并键**

- **只认学号（已选）**：唯一、可解释；姓名可能重复/改名，不拿来做键。代价是只有姓名的名单不能合并。
- 学号优先、缺学号按姓名：能覆盖更多名单，但重名/改名会误配；v1 不做。
- 重复学号：禁用合并，不取第一条；避免悄悄配错。

**列映射**

- 自动识别 only：表头必须叫别名，自定义表头（`编号` / `总分`）无法正确导出。
- **自动 + 手动四个下拉（已选）**：别名只当默认值，用户可把任意列指定为学号/姓名/成绩/序号；预览实时重算。代价是对话框多四个下拉。
- **存储 `roles`（已选）**：既然列名可能不叫别名，导出必须按导入时的映射写回；只存 `headers` 会认不出角色，还会重复补列。

**文件里的成绩**

- **不采用（已选）**：导入永远从本机成绩出发；合并只保留本机 `entry`；避免“文件旧成绩覆盖本机新成绩”。代价是导出文件不能当存档恢复。
- 采用文件成绩：能跨设备恢复，但会和本机成绩/合并语义打架；v1 不做。

**编辑**

- **复用计算器草稿 + 浮动到行旁（已选）**：一套求值/基数/操作数逻辑；手机上不用滚回键盘；草稿自带“保存并完成”。
- 行内直接改成绩：只能改一个数，改不了多笔算式；弃用。
- 弹窗编辑器：和计算器重复，且多一层；弃用。

**编辑目标切换**

- **名单模式下阻止切换（已选）**：编辑中再点另一行的编辑，提示先保存/取消；避免浮动草稿上的未保存数字被静默丢掉。
- 静默重定向（现状）：和现有 `beginEdit` 一致，但在长名单 + 浮动草稿上更容易误触；名单模式不用，无名单模式保持现状。
- 弹确认框：能切换但要额外一步；v1 不做。

**结果后暂停**

- **保留（已选）**：与设置一致，防止下一位的数字抢到上一位结果后面；想快改 0。代价是默认每人多约 1 秒。
- 名单模式跳过：最快，但误触会串位；用户已明确选保留。

**自动按等号**

- **算一次成功计算并回填（已选）**：与“满 N 笔自动算”的意图一致；结果后暂停给一拍确认。
- 只算不填：会让“自动等号”和“回填”脱节，用户还得再按一次；弃用。

**语音**

- **只念结果（已选）**：现有引擎对姓名/生僻字可能 OOV，念“第几位/下一位”要新增句子和测试；v1 不动语音，只保证名单模式仍念结果。
- 名单感知（念序号/下一位/姓名）：更适合不盯屏幕，但把语音和名单耦合；留到后续。

**对话框与计时/键盘**

- **打开任何 dialog 停自动确认 + keydown 直接 return（已选）**：否则重导入预览时自动确认会在背后写旧名单、物理键盘会改计算器，破坏“取消不变”。
- 只停设置面板（现状）：不够；导入对话框是新入口。

**持久化**

- **localStorage（已选）**：50 行足够，同步读写简单；键 `cal-phone.roster.v1`。
- IndexedDB：更强但异步、复杂；不需要。

**导出**

- **只导成绩（已选）**：交付物是分数表；算式留在页面可查。
- 加算式列：便于审计，但改变交付格式；v1 不做。

**撤回**

- **不做名单级撤回（建议）**：误录用编辑；少一个状态。
- 做“撤回上一位”：更快，但要处理下一位指针/存储/焦点；v1 不做。

**布局**

- **手机一律两行卡片（已选）**：320/390 都不挤；不做 5 列表格。
- 宽屏表格：当前产品是手机单文件，不需要。

**粘贴**

- **加“粘贴名单”（建议）**：手机上班群名单常常不是文件；同一套解析/映射/预览；不做 xlsx。
- 只选文件：少一个入口，但手机上更麻烦。

## 6. 约束

- 保持单文件、自包含、无外部依赖；不引入框架、构建步骤、网络请求。
- 沿用现有状态机（`select / input / result / error / edit`）、float64 从左到右折叠、`formatValue` 口径、自动确认/自动等号/基数/结果后暂停/语音/震动。
- 现有 `tests/suite.mjs` 全部 18 个场景在不导入名单时必须继续通过（尤其编辑追加、刷新清空、布局、确定性）；`tests/voice/run.mjs` 继续通过。
- 新行为用 `tests/scenarios/roster-*.mjs` 覆盖，选择器沿用 `data-testid` 风格；新增 hook：
  - 名单：`roster`、`roster-summary`、`roster-list`、`roster-row`（`data-seq`、`data-filled`、`data-name`、`data-id`、`data-next`）、`roster-score`（`data-value`）、`roster-expression`、`roster-edit`、`roster-next`（`data-seq`）、`roster-presence`
  - 工具：`roster-import`、`roster-export`、`roster-clear`、`roster-file`、`storage-warning`、`roster-data-warning`
  - 导入：`import-dialog`（`data-error`、`data-mode`）、`import-summary`（`data-count`、`data-keep-count`、`data-drop-count`、`data-new-count`）、`import-map`（`data-id-index`、`data-name-index`、`data-score-index`、`data-seq-index`）、`import-id-column`、`import-name-column`、`import-score-column`、`import-seq-column`、`import-map-note`、`import-columns`、`import-preview`、`import-warning`、`import-mode`、`import-mode-keep`、`import-mode-clear`、`import-select`、`import-paste`、`import-paste-text`、`import-paste-parse`、`import-paste-back`、`import-sample`、`import-confirm`、`import-reselect`、`import-cancel`、`import-error`
  - 编辑：`edit-draft-title`、`edit-done`；保留现有 `edit-draft`、`operand-input`、`operand-remove`、`edit-cancel`
  - 名单行编辑不再复用 `history-item` / `history-edit`；无名单历史仍用它们。

**Hook 契约（存在/缺失与属性）**

| hook | 何时存在 | 关键属性/文本 |
| --- | --- | --- |
| `roster` | 有名单 | `role="list"` |
| `roster-summary` | 有名单 | `N 人 · 已录 K · …` |
| `roster-list` | 有名单 | 行容器 |
| `roster-row` | 每行 | `data-seq` 1..N、`data-filled="true|false"`、`data-name`、`data-id`；`data-next="true"` 只在下一行，其他行没有该属性 |
| `roster-score` | 每行 | 已录有 `data-value`（`formatValue`）；未录文本 `—`、无 `data-value` |
| `roster-expression` | 每行 | 已录为算式文本；未录为空字符串 |
| `roster-edit` | 已录行 | `aria-label="编辑第 3 位 李四 的成绩"`；无姓名/学号时 `编辑第 3 位的成绩` |
| `roster-presence` | 有名单 | `下一位 … · 按 = 记入成绩` 或录满提示；无名单时不存在 |

## 7. 验收场景

1. **解析**：UTF-8 BOM / 无 BOM / GBK 各一次；逗号/分号/制表符；LF/CRLF；列顺序打乱；缺学号、缺姓名、两者都有；额外列；`姓名/名字` 同义列；引号姓名含逗号/引号/换行；空行穿插；0 字节/仅空行/表头全空/二进制垃圾被拒且状态不变；样例下载。
2. **列映射**：默认别名（含多同义列取最左）；把 `编号` 指定为学号、`学生` 为姓名、`总分` 为成绩、`No.` 为序号后，预览/人数/前 3 行/列标签正确；改映射实时重算；学号/姓名都 `无` 时确认禁用；同一列不能两用；成绩/序号 `无` 时导出补列；自定义表头刷新后仍按 `roles` 导出。
3. **导入方式**：已有 20 条成绩时出现单选，默认保留；同学号乱序、改名、新增、删除的预览计数正确；选保留后成绩落到正确的人；选清空后全空；K=0、无学号列、新旧名单重复学号时只提供清空并说明，保留单选项不渲染、不显示 K/D/A、`data-mode="clear"`；改映射导致保留不可用时自动切清空；取消/Esc 后旧名单/成绩/计算器不变。
4. **导入归零与守卫**：先无名单算 2 条并停在结果态，再导入 3 人；历史/成绩清空、3 行全空、下一位 1、计算器回 `select`（无运算符、算式/结果/输入框空、草稿不可见、自动确认/结果后暂停/语音队列已清）；取消则历史仍 2 条、状态不变；在自动确认计时中打开导入并等待超过 t 秒，取消后输入框/状态不变；对话框打开时按数字/回车/等号不改变计算器。
5. **顺序回填**：3 人依次算 3 个成绩；行 1/2/3 依次落值，序号/姓名对应，下一位 1→2→3→无；第 4 次有结果不写名单、状态行提示录满、行数仍 3；除零/空/非法不消耗下一位；基数快照进每条记录；自动等号（设 N=2）能回填并推进。
6. **结果后暂停**：`=` 后立刻按数字被忽略（结果/名单不变），1 秒后可输入；设 0 后立刻可输入；暂停期间状态行仍显示“已记录”。
7. **编辑同步**：3 人录满后编辑第 2 行，改操作数并 `=`；第 2 行成绩/算式更新，序号/姓名不变，行数 3，第 1/3 行逐字段不变；刷新后仍是新值；下一位仍“无”；50 人录满后滚到末行点编辑，草稿在视口内、被编辑行在草稿上方；保存后焦点回到该行编辑按钮；取消后行不变、焦点回到编辑按钮；编辑第 2 行时点第 3 行编辑，状态/草稿/第 2 行不变、提示先保存或取消，取消后第 3 行可编辑；无名单模式编辑仍追加。
8. **序号**：名单行与导出 CSV 的序号都是 1..N；名单模式不渲染 `history-item`；无名单历史没有序号。
9. **导出**：BOM、CRLF、列顺序/`roles`（含自定义表头）、缺序号前补、缺成绩后补、映射成绩列覆盖、未映射成绩列保留原值并补列、未录为空字符串、已录为 `formatValue`、引号/逗号/换行按 RFC4180、文件名含原名与日期、导出不改变页面/存储、导出文件重新导入时成绩不采用。
10. **持久化**：导入并录 2 条后读存储（`version/headers/roles/rows/entry`）并刷新，名单/成绩/顺序/下一位/`roles` 恢复，计算器回 `select`；清除后刷新回无名单且历史空；`localStorage` 抛错时不崩、仍可录入、`storage-warning` 可见；坏 JSON/未知 version/缺 `roles`/角色非法时忽略、不覆盖原值、`roster-data-warning` 可见。
11. **布局**：320×568（CDP）与 390×844 下，导入入口/粘贴/预览四下拉/导入方式/3 行/50 行/编辑浮动草稿/下一位标记均无横向溢出；可见控件 ≥44px；输入字号 ≥16px；名单正文 ≥13px；对话框焦点/Esc/焦点返回；`roster` 列表语义；编辑按钮 `aria-label` 含序号与姓名；`下一位` 有文字。
12. **回归/无错误/确定性**：不导入名单时 `tests/suite.mjs` 全绿；`tests/voice/run.mjs` 全绿；新 `roster-*` 场景全绿；全流程 `pageerror` / console error 为 0；同一导入+映射+保留/清空+录入+编辑序列在两个全新上下文得到相同名单、成绩与导出 CSV。

## 8. 留给实现者的决定

- 名单卡片的 DOM 结构、CSS 断点、省略规则；卡片在 390px 是否两列（建议单列）。
- 导入对话框的排版、滚动、焦点顺序；四个下拉在 390px 的 2×2 网格细节。
- 表头别名的最终默认集合（可在给定 4 组上补充；必须保留“用户可手动覆盖”）。
- 导出文件名非法字符清理的具体实现。
- 名单工具条在 320px 下的折叠/换行。
- 存储写入的节流/批量策略（当前规模逐次写入即可）。
- 新测试文件的拆分（建议 `roster-import / roster-import-mode / roster-fill / roster-edit / roster-export / roster-storage / roster-dialog`）。
- CSV 转义细节（必须 RFC4180，导出文件能被自身重新导入）。
- 名单模式“保存并完成/取消”与无名单“关闭”的切换实现（同一按钮换文案/行为，或两套按钮显隐）。
- 浮动草稿用 `position: fixed` 还是 `sticky`；底部 padding 与软键盘 `visualViewport` 的处理。
- `roles` 用与 `headers` 对齐的数组（建议）还是对象；存储校验的具体字段。
- 坏数据提示的文案微调（保持与 `storage-warning` 分开的两个 hook：一个“不可用”，一个“无法读取”）。
- 合并预览是否列出被丢弃的姓名/学号（建议最多列 3 个）。
- 粘贴名单的 textarea 高度、是否默认展开（建议按需展开）。
- 清除确认用原生 `confirm()` 还是页内二次确认（两者都可，测试要兼容）。
- 导入/清除后的页面滚动位置（建议不强制滚动，计算器在上方）。
