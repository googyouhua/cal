# 名单导入与成绩回填

- 日期：2026-11-19
- 状态：待批准
- 范围：`index.html`（单文件计算器）与 `tests/`（Playwright 场景）
- 规模：项目（新数据模型 + 导入/导出 + 名单表 UI + 编辑语义 + 测试）

## 1. 为什么做

这个计算器现在用于**统分**：一份成绩由若干笔分组成，按“=”算出一个总分。但名单在 Excel 里，成绩在页面历史里，两边是断开的：算完一个人要手抄回表格；改了一个人的历史，表格不会跟着变。

目标：导入一份带顺序的名单，按名单顺序连续统分；每个成功计算自动落到下一位头上；编辑某人的成绩就改那一行；随时导出一份能直接交的 CSV。

用户故事：

> 我有一份 50 人的名单。导入后从第 1 位开始录，每算完一个人自动记到他的名字后面并跳到下一位。录到第 20 位发现第 3 位算错了，点第 3 行的编辑改掉，导出时第 3 行就是新成绩。中途手机锁屏、刷新，已录的不会丢。

## 2. 已定行为

### 2.1 导入名单

**文件类型**：只做 CSV。`.xlsx` 浏览器读不了；要么打包解析库（违背单文件无依赖），要么自己解 zip + XML（共享字符串、多工作表、日期格式都要自己兜，手机上难排错）。导入面板给一个「下载样例名单」按钮，并在文案里写“Excel 里选‘另存为 → CSV UTF-8（逗号分隔）’”。

**编码**：兼容 UTF-8（带/不带 BOM）与 GBK。先按 UTF-8 解码，若结果含替换字符 `U+FFFD`，改用 GBK 重解。中文 Windows 上 Excel 的默认“CSV（逗号分隔）”是 GBK，“CSV UTF-8”带 BOM，两者都要能读。

**分隔符**：逗号、分号、制表符自动识别（在表头行里取出现次数最多的一个）。

**表头**：第一行必须是表头。至少包含「姓名」或「学号」之一，否则拒绝导入并给出可读提示。可识别的列名：

| 含义 | 可接受的表头 |
| --- | --- |
| 序号 | `序号`（可选；程序不采用其值，见下） |
| 学号 | `学号`、`考号`、`学籍号` |
| 姓名 | `姓名`、`名字`、`学生姓名` |
| 成绩 | `成绩`、`分数`、`得分`（可选；导入时忽略其值） |

- 列顺序任意；无法识别的列**原样保留**（如 `班级`、`组别`），导出时按原列顺序写回。
- 同一含义出现多列时（如同时有 `姓名` 和 `名字`）：**按从左到右取第一列**，后面的同义列当作普通列原样保留，不丢数据；预览里把这种列标成“保留列”。
- **序号 = 名单行顺序 1..N，由程序生成**。文件里的「序号」列不参与编号（导出时该列写回 1..N）。如果用户的编号是考号之类、不是 1..N 的顺序号，应放在「学号」列或自定义列里。顺序始终等于文件行顺序。
- 空行跳过；姓名和学号都为空的非空行跳过。
- 文件里的成绩值**不采用**：导入即新一轮，全部从空成绩开始（见 2.4）。

**导入流程**（一个对话框，两段式；不直接生效）：

1. 点击「导入名单」→ 打开导入对话框。第一段是说明与入口：
   - 一句话格式说明：`第一行是表头，至少要有「姓名」或「学号」；Excel 请另存为 CSV UTF-8。`
   - `下载样例名单`（下载一份 3 行的 CSV，带 BOM）。
   - `选择文件`（`accept=".csv,text/csv"`，隐藏的 file input）。
   - `取消`。
2. 选中文件并解析成功后，同一对话框切到第二段预览：`识别到 N 人`、识别到的列（含保留列）、前 3 行（序号 / 学号 / 姓名 / 成绩留空）、以及提示语：
   - 当前已有成绩：`导入会清空当前 N 条成绩，从第 1 位重新录入。`
   - 当前无成绩：`导入后从第 1 位开始录入。`
   - 按钮：`开始录入`（主）/ `重新选择` / `取消`。
3. 点「开始录入」才真正替换名单，并把**整个计算器归零**：清空名单与成绩、清空历史、退出编辑态（丢弃草稿，不恢复编辑前画面）、运算符回到未选、操作数/算式/结果清空、主输入框清空、停止自动回车计时、回到 `select` 态、从第 1 位开始。点「取消」或关闭对话框，当前状态完全不变。
4. 解析失败（无表头、没有姓名/学号列、空名单、编码无法识别）时，对话框里显示原因并保留「重新选择」，当前名单和成绩不变。

**清除名单**：名单工具条里的「清除名单」，二次确认（`清除后本机保存的名单和 N 条成绩都会删除。`），确认后删除本机存储、名单与成绩清空、计算器归零回 `select`、回到无名单模式；无名单模式的历史从空开始。

### 2.2 名单表

导入成功后，原来的「计算历史」区变成**名单成绩**区：

- 标题行：`名单成绩` + 工具条 `导入` / `导出` / `清除`。
- 摘要行：`50 人 · 已录 2 · 下一位 3 李四`（没有姓名时显示学号；两者都没有显示 `第 3 位`）。
- 每一行按名单顺序显示：`序号`、`姓名`、`学号`、`成绩`、`编辑`。
- 已录入的行在第二行显示完整算式与成绩（与现有历史条目的 `算式 … 结果` 两行形态一致），保留“这个分是怎么算出来的”的可查性；未录入的行只显示 `—` 占位，没有算式。
- 未录入的行成绩显示 `—`，没有编辑按钮（没有可编辑的内容）。
- 下一行（序号最小的空成绩行）带可见标记：行底色高亮 + `下一位` 小标签。
- 已录入的行显示完整成绩（与计算器同一 `formatValue` 口径），编辑按钮可点。
- 列表按名单顺序**升序**，不按最新在上；最新录入会出现在下方。
- 列表随页面滚动，不做内部滚动区；50 人也不会把计算器挤出屏幕（计算器始终在上方）。
- 从名单下方的行点「编辑」时，页面**自动把编辑草稿滚入视野**（`scrollIntoView({ block: "nearest" })`），否则在手机上看起来像没反应；保存或关闭后把被编辑的那一行滚入视野，焦点回到该行的编辑按钮。

**窄屏（320px）**：一行改成两行卡片式布局，避免 5 列挤压：

```text
3  李四 · 20230101              [下一位]
12 + 30 + 8 = 50                 [编辑]
```

未录入行：

```text
4  王五 · 20230104
成绩 —
```

姓名、学号都没有时第一行显示 `第 3 位`。长姓名/长学号单行省略，不换行撑破布局。

**录入时的“下一位”可见性**：名单加载后，计算器显示区上方常驻一行小字 `下一位 3 李四`；录入过程中不需要滚到列表底部确认下一位是谁。没有名单时这一行不出现。

### 2.3 计算与回填

- 按 `=` 且计算成功（有限结果）时：
  - 若名单里还有空成绩行：把结果与完整计算记录写入**序号最小的空成绩行**，然后该行变成已录入，下一位自动后移。
  - 若名单已录满：结果照常显示在计算器上，但**不写名单、不新增行**；状态行提示 `名单已录满（50 人）；如需修改请点行内编辑`。
  - 除零、非法输入、没有操作数的 `=`：不写名单、不消耗下一位（沿用现有行为）。
- 写入的记录与原来历史条目同构，并带上 `seq`：
  `{ seq, operator, operands: [{value, display}], base, expression, result }`
- 状态行在成功后显示 `已记录 3 李四：37.7；下一位 4 王五`（没有下一位时显示 `已记录 …；名单已录满`）。
- 运算符沿用、基数快照、自动回车、退格撤回等现有行为全部不变；基数按每条记录自己的快照保存。
- 名单模式下，历史条目的序号显示为 `3 李四`（没有姓名则 `3` 或 `3 · 学号`），并带 `data-seq` 属性供测试读取。

### 2.4 编辑与同步

名单模式下，点击某条已录入行的「编辑」：

- 复用现有编辑草稿（运算符、操作数 chip、基数标记、关闭按钮、点选替换、换运算符、删除、追加）。
- 编辑态顶部提示 `正在编辑 3 李四 的成绩`。
- 按 `=` 重算成功后，**原地替换那一行**：
  - 序号不变、姓名/学号不变、行位置不变、总行数不变；
  - 成绩、算式、运算符、操作数、基数快照一起更新；
  - 不消耗下一位，也不新增行；
  - 若其他空行还在，下一位指针不变。
- 编辑态按「关闭」：丢弃草稿，行内容不变（沿用现有快照恢复）。
- 编辑态出现空值/非数字/除零：沿用现有 no-op / 错误态，那一行保持原样。
- 编辑后立刻保存到本机（见 2.5）。

**这条只作用于名单模式。** 无名单模式下，编辑后仍按现有契约“追加一条新记录、原记录保留”，不改动旧行为与旧测试。

### 2.5 持久化

- 存储键：`cal-phone.roster.v1`，值为：
  ```json
  {
    "version": 1,
    "fileName": "高一3班.csv",
    "headers": ["序号", "学号", "姓名", "成绩", "班级"],
    "rows": [
      { "seq": 1, "id": "20230101", "name": "张三", "extra": ["高一3班"], "entry": null },
      { "seq": 2, "id": "", "name": "李四", "extra": [""], "entry": { "seq": 2, "operator": "+", "operands": [], "base": null, "expression": "…", "result": 37.7 } }
    ]
  }
  ```
  （`headers` / `extra` 保留原始列，用于导出；`entry` 为 `null` 表示未录入。）
- 每次会改变名单或成绩的操作后立即写入：导入、成功 `=`、编辑成功。
- 页面启动时读取：名单、成绩、列表顺序、下一位高亮都恢复；计算器回到初始 `select` 态（不恢复上一次算式）。
- `localStorage` 不可用或写入失败：页面继续以内存方式工作，名单区显示一条不可关闭的提示 `本机存储不可用，刷新会丢失成绩。`；不抛错、不阻断录入。
- 数据读取失败或版本不认识：忽略这份存储，回到无名单模式，不覆盖原数据。
- 「清除名单」删除该键；无名单模式下历史仍只存当前页面（刷新清空），**不写任何历史存储**。
- 设置（自动回车、基数）仍用原来的 `cal-phone.settings.v1`，与名单互不影响。

### 2.6 导出

- 「导出」随时可用（未录完也能导）。
- 生成 CSV（UTF-8 **带 BOM**，逗号分隔，CRLF 行尾），列 = 原文件列顺序；原文件没有「序号」列时在**最前面**补一列 `序号`；没有「成绩」列时在**末尾**补一列 `成绩`。
- 「序号」列写 1..N（原文件里的同名旧值被覆盖）；「学号」「姓名」按名单；「成绩」写格式化后的结果，未录入留空；其他列原样写回。
- 文件名：`<原文件名去掉扩展名>-成绩-YYYYMMDD.csv`。
- 下载通过 `Blob` + `<a download>`，在 `file://` 下也能用；导出后状态行提示 `已导出 N 人（M 条成绩）`，不改动页面或存储。
- 导出不自动触发；不在每次计算后弹下载。

### 2.7 无名单模式（保持现状）

没有导入过名单、或清除了名单时：

- 计算历史仍是最新在上的会话内列表，刷新清空，不写存储。
- 历史条目没有序号。
- 编辑后追加新记录、原记录保留。
- 导入入口在「计算历史」标题旁（`导入名单`），首次使用者能找到。

### 2.8 布局与可达性

- 单文件、无外部依赖、无网络请求；`file://` 直接打开可用。
- 320×568 与 390×844：导入/导出/清除、预览对话框、名单行、编辑态均无横向溢出。
- 可见交互控件宽高 ≥ 44×44 CSS px；输入字号 ≥ 16px；名单行正文不小于 13px。
- 名单表用列表语义（`role="list"` / 每行 article 或 table 语义），每行编辑按钮 `aria-label="编辑第 3 位 李四 的成绩"`；`下一位` 标记不能只靠颜色，要有文字。
- 导入预览对话框用原生 `<dialog>`，Esc 可关，焦点进入主按钮，关闭后焦点回到导入按钮。
- 导入/导出入口在名单区标题行，不需要滚过整张名单才能点到。

## 3. 非目标

- 不解析 `.xlsx`、不内置表格库。
- 不支持同时打开/切换多份名单；一次一份，换名单 = 重新导入。
- 不做账号、云同步、多人协作、冲突合并。
- 不做缺考/跳过、并列名次、平均分、去掉最高最低分等统计。
- 不做名单内改名、改学号、拖动排序、增删行。
- 不做一人多条成绩或累计；一人一条。
- 不做“导入带成绩的文件继续录”；导入永远是新一轮。
- 不做成绩小数位设置、四舍五入、百分制换算。
- 不做自动导出、自动下载、导出到原文件路径（浏览器做不到）。
- 不改自动回车、基数、运算符沿用、退格撤回、除法错误处理的既有语义。

## 4. 反目标（做到了也算失败）

- 导入后还能看到上一份名单的序号或成绩。
- 编辑后行数变了、序号变了，或多出一条“新记录”。
- 编辑第 2 位后，下一位从第 2 位重新开始（覆盖已录的第 3 位）。
- 刷新后成绩丢失，或名单与成绩对不上。
- 导出的 CSV 用 Excel 打开中文乱码，或未录成绩写成 `0`/`NaN`。
- 320px 下导入对话框、名单行或编辑态横向溢出；控件小于 44px；输入字号小于 16px。
- 名单录满后静默吞掉结果（必须有可见提示）。
- 导入后计算器还留着上一份名单的运算符、已输入数字或上一次结果，导致第一笔成绩串到新名单上。
- 无名单模式的任何现有行为、现有测试发生变化。
- 页面引用任何外部 http(s) 资源，或引入构建步骤/依赖。

## 5. 方案与取舍

**名单与历史的摆法**

- **A（已选）名单就是历史表**：导入后列表换成名单成绩表，未录行占位，下一位高亮，行内编辑原地改。
  - 只有一份数据，不存在“名单”和“历史”谁是真值的问题；一眼看到进度。
  - 代价是列表不再是时间线，最新录入在下方；需要常驻的“下一位”提示补足。
- B 名单面板 + 现有历史并存：同一成绩显示两遍，两份数据要一直同步，最容易出现“改了历史名单没变”的 bug，弃用。
- C 只提示“下一位”：最省地方，但看不到谁没录，用户要求“名单数据同步”却看不到名单，弃用。

**编辑语义**

- **名单模式下原地覆盖**（已选）：序号是唯一行标识，追加新记录会造成同一序号两条、名单不知信谁。
- 无名单模式保持“追加新记录、原记录保留”：这是之前验收过的契约，不做全局推翻；两套语义按模式隔离，旧测试不动。

**持久化**

- **只在名单模式持久化名单 + 成绩**（已选）：不存就白录；无名单模式保持会话性，延续旧契约。
- 不把历史单独持久化成另一份数据：名单行里的 `entry` 就是唯一真值，避免两份数据漂移。

**导入即新一轮**

- 用户明确要求“导入后历史清空、重新计算”。导入文件里的成绩列不采用，避免旧成绩与新序号混在一起；要续录就靠本机存储，不靠重新导入。
- 代价：导出的成绩文件不能当“存档再导入”用。这是有意的：导出是交付物，不是工程文件。

**序号**

- **序号 = 行顺序 1..N**（已选）。名单的“顺序”就是文件行顺序；文件里的「序号」列不参与编号，导出时写回 1..N。
- 不采用文件序号可以保证唯一、无空洞、与“第几位”一致；代价是如果用户把考号命名为“序号”，会被重写。文案里明确：编号类数据请放「学号」。

**CSV 而非 Excel**

- CSV 是唯一不引依赖又能被 Excel/WPS 双向读写的选择；用 UTF-8 BOM + GBK 兼容把乱码风险压到最低。

## 6. 约束

- 保持单文件、自包含、无外部依赖；不引入框架、构建步骤、网络请求。
- 沿用现有状态机（`select / input / result / error / edit`）、float64 从左到右折叠、`formatValue` 口径。
- 现有 `tests/suite.mjs` 全部场景在不导入名单时必须继续通过（尤其编辑追加、刷新清空）。
- 新行为用 `tests/scenarios/` 新场景覆盖，选择器沿用 `data-testid` 风格；新增 hook：
  - `[data-testid="roster"]`、`[data-testid="roster-summary"]`、`[data-testid="roster-row"]`（带 `data-seq`、`data-filled`）、`[data-testid="roster-score"]`、`[data-testid="roster-expression"]`、`[data-testid="roster-edit"]`、`[data-testid="roster-next"]`
  - `[data-testid="roster-import"]`、`[data-testid="roster-export"]`、`[data-testid="roster-clear"]`、`[data-testid="roster-file"]`（隐藏的 file input）
  - `[data-testid="import-dialog"]`、`[data-testid="import-summary"]`、`[data-testid="import-sample"]`、`[data-testid="import-confirm"]`、`[data-testid="import-cancel"]`
  - 名单行编辑仍复用 `history-item` / `history-edit` 语义时，保留可读的兼容属性；测试以新的 `roster-*` 为准。
- 编码、导出文件名等实现细节在无头 Chromium 下可测；不依赖真实 Excel 或人工。
- 外部前提：无需账号、服务、真实设备或人工授权；验收在无头 Chromium 中完成。

## 7. 验收场景

1. **导入解析**：UTF-8 BOM、UTF-8 无 BOM、GBK 三种编码各导入一次，人数与姓名正确；逗号/分号/制表符各一次；列顺序打乱、缺学号、缺姓名、姓名学号都有、含额外列，均能导入；无表头 / 无姓名且无学号 / 空文件被拒绝且当前状态不变；同时有 `姓名` 和 `名字` 时取左列、另一列原样保留并在导出中出现；导入对话框能下载样例 CSV。
2. **导入即重置**：先无名单算 2 条历史并停留在结果态（带运算符与结果），再导入 3 人名单；历史/成绩清空、列表 3 行全空、下一位为 1、计算器回到 `select`（无 `data-operator`、算式与结果为空、`calc-input` 为空）、编辑草稿不可见；点取消则历史仍 2 条、计算器状态不变。
3. **顺序回填**：3 人名单依次算 3 个成绩；行 1/2/3 依次落值，序号与姓名对应，下一位高亮从 1→2→3→无；第 4 次计算有结果但不写名单，状态行提示录满，行数仍 3。
4. **编辑同步**：3 人全部录完后编辑第 2 行，改一个操作数并 `=`；第 2 行成绩与算式更新、序号/姓名不变、行数仍 3、第 1/3 行逐字段不变；刷新后仍是修改后的值；编辑第 2 行后下一位仍为“无”（不因编辑产生新空位）；从 50 人名单的最后一行的编辑入口进入编辑态时，编辑草稿在视口内可见。
5. **序号**：名单行与导出 CSV 的序号都是 1..N；无名单模式的历史没有序号。
6. **导出**：导出 CSV 带 BOM、列顺序与原文件一致（原文件无序号时最前面补 `序号`，无成绩时末尾补 `成绩`）、未录入为空字符串、已录入为 `formatValue` 结果、同时含重复同义列时两列都在；文件名含原名单名与日期；导出不改变页面状态。
7. **持久化**：导入并录 2 条后刷新，名单、成绩、下一位、列表顺序全部恢复，计算器回到 select；清除名单后刷新回到无名单模式且历史为空；`localStorage` 抛错时不崩、仍可录入。
8. **布局**：320×568 与 390×844 下，导入对话框、3 行与 50 行名单、编辑态、未录/已录/下一位标记均无横向溢出；可见控件 ≥44px；名单正文与输入字号达标。
9. **回归**：不导入名单时，现有 `tests/suite.mjs` 全绿（含编辑追加一条、刷新清空、除法错误、布局、确定性）。
10. **无错误**：全流程 `pageerror` 与 console error 为 0；同一导入 + 录入 + 编辑序列在两个全新上下文得到相同名单与成绩。

## 8. 留给实现者的决定

- 名单表的 DOM 结构（table 还是 article 列表）、CSS 断点与省略规则的具体写法。
- 导入预览对话框的排版、`<dialog>` 的锚定与焦点细节；文件选择器是 `<input type=file hidden>` + 按钮，还是 `showOpenFilePicker`（不要求，后者兼容性差）。
- 表头别名的最终集合（可在设计给的 4 组基础上补充常见的同义词，但必须保持“至少姓名或学号之一”的规则）。
- 导出文件名的具体格式与非法字符清理。
- 名单工具条在 320px 下的折叠方式（例如导入/导出用图标 + aria-label，或换行）。
- 存储写入的节流/批量策略（当前规模逐次写入即可）。
- 新测试文件的拆分（建议 `roster-import / roster-fill / roster-edit / roster-export / roster-storage` 五个场景文件）与选择器命名。
- 姓名/学号含逗号、引号、换行时的 CSV 转义细节（导出必须按 RFC 4180 加引号；导入至少要能读回自己导出的文件）。
