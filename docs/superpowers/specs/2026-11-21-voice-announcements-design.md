# 语音播报：按键播报 + 结果播报（sherpa-onnx 离线 TTS）

- 日期：2026-11-21
- 状态：待批准
- 范围：`index.html`、`voice/`（可选静态资源，git 忽略）、`scripts/`、`tests/voice/`、`deploy/`、`README.md`
- 规模：项目级改动（引入约 96MB 离线 TTS 资源与加载/播放/排队链路），不再是小改动

## 1. 为什么做

统分时用户不一直盯屏幕，想靠耳朵确认每个数字都按上了：漏按一位，整份分就错了。加两个独立开关：

- **按键播报**：每按一个数字/小数点/退格/确认/运算符，念出这个键。
- **结果播报**：按 `=`（含自动按等号）后念出结果；除零念错误。

默认关闭。引擎使用 `/ws/voice` 已验证的 **sherpa-onnx 1.13.5 WASM + Matcha-TTS（中文女声）**，本地静态资源，不走公网、无构建步骤。

## 2. 技术事实（已在 /ws/voice 与本机 spike 验证）

`/ws/voice` 的 `speakSherpa` 路径已在桌面 Chromium 验证通过。本次另做了一个最小 spike（临时页面 + 本地 HTTP，无 COOP/COEP）：

| 事实 | 测量 |
| --- | --- |
| 运行时 | `sherpa-onnx-wasm-web.js/.wasm` 1.13.5 + `sherpa-onnx-tts.js`，`createOfflineTts` 可用 |
| 模型 | Matcha `matcha-icefall-zh-baker` + HiFiGAN v2，采样率 22050Hz，单说话人 |
| 资源总量 | 7 个文件，95,749,505 字节 ≈ **96MB**（91MiB）；其中声学模型 72MiB、wasm 14.9MB |
| 初始化 | 桌面 headless：模块 150ms、4 个模型文件读盘 400ms、引擎创建 + 首句合计约 4s |
| 跨域隔离 | **TTS 不需要** COOP/COEP：`crossOriginIsolated=false`、`SharedArrayBuffer` 不存在时仍正常合成。COOP/COEP 是 `/ws/voice` 的 ASR 路径需要，本功能不依赖 |
| 阿拉伯数字 | 模型把 `37`、`7` 视为 OOV 直接忽略：`结果 37.7` 只念出「结果」。**必须先用 /ws/voice 的 `numberToChineseReading` 转成中文**（`结果 三十七点七`） |
| 单句耗时 | 按键词 142–249ms/句；`结果 三十七点七` 487ms；`不能除以零` 346ms（同步阻塞主线程） |
| 按键词时长 | 数字 0.19–0.28s、点 0.23s、退格 0.45s、确认 0.53s、运算符 0.24–0.28s；峰值 0.17–0.61 |
| 预合成 | 17 个按键词全部合成约 3.0s（一次性），之后按键播放无需再跑模型 |
| 许可 | 训练数据来自 Baker 数据集，**仅限非商用**（模型卡与 /ws/voice README 已注明） |

结论：按键词可以**预合成缓存**，把每次按键的延迟降到播放本身；结果句子只能按需合成，接受约 0.3–0.5s 的主线程卡顿。

## 3. 用户可见行为

### 3.1 设置入口

齿轮面板新增「语音播报」一组，放在基数之后：

- 两个复选框（复用 `.settings-toggle-row` / `.settings-checkbox`，≥44px）：
  - **按键播报**（`settings-voice-keys`）
  - **结果播报**（`settings-voice-result`）
- 提示文案：首次开启需下载约 96MB 离线语音资源；手机静音或媒体音量为 0 时不会出声；模型仅限非商用。
- 状态行（`aria-live="polite"`）+ 进度条 + 「重试」按钮：
  - `正在加载语音引擎…`
  - `正在下载语音模型 42%（约 96MB，仅首次）`
  - `正在准备按键语音 8/17`
  - `语音已就绪`
  - `语音加载失败：<原因>` + 重试
- 主界面右上角复用现有 `settings-summary` 胶囊：加载/准备时显示 `语音准备中 42%`，失败时显示 `语音不可用`，就绪且已自定义时显示 `已自定义`。这样设置面板关着时，用户也知道“为什么按键还没声”。
- 任一开关开启即算「已自定义」（齿轮琥珀点 + 摘要）。
- 浏览器不支持（`file://` 打开、无 WebAssembly 或 AudioContext）时，两个开关禁用，提示改用 `http(s)` 网页地址。当前共享 suite 用 `file://`，因此语音不会在回归基线里触发网络。

### 3.2 按键播报

只在动作真的发生时出声：

| 动作 | 播报 |
| --- | --- |
| 数字 0–9 | 零 / 一 / 二 / 三 / 四 / 五 / 六 / 七 / 八 / 九 |
| 小数点 | 点 |
| 重复输入小数点（被忽略） | 不出声 |
| 退格：删掉一个字符，或撤回最后一笔 | 退格 |
| 退格：输入为空且无可撤回 | 不出声 |
| 确认：成功收进一笔 | 确认 |
| 确认：输入为空 | 不出声 |
| 运算符 `+ - * /` | 加 / 减 / 乘 / 除（编辑草稿里换运算符也算） |
| `=` | 不发声，交给结果播报；结果播报关闭时 `=` 静音 |

- **自动确认**（停顿后自动收数字）等同于按了「确认」，也播「确认」。
- 从 `=` 直接提交未确认数字时，不播「确认」，直接播结果。
- 屏幕键盘与物理键盘走同一动作函数，行为一致。
- 编辑草稿里直接往操作数输入框打字**不播报**（粘贴、长按、整段替换会乱念），见非目标。

### 3.3 结果播报

- `=` 计算成功后播「结果 <中文读法>」，如 `结果 十八点七`。
- 负数的前导 `-` 读成「负」；`-0` 读「零」；整数、小数、千分位、全角数字复用 `numberToChineseReading`（从 /ws/voice 原样移植并注明来源）。
- 自动按等号（满 N 笔）同样播结果。
- 除零等错误播「不能除以零」，不加「结果」前缀。
- 不播算式；照屏幕结果转中文，不改写、不四舍五入。
- 与按键播报相互独立：只开结果时按键静音、结果照播；只开按键时结果静音。

### 3.4 排队与打断

- 自维护一个串行队列，不把多条直接塞给 `speechSynthesis`/引擎。
- 每条任务：`{kind: key|result|sample, text, samples?, sampleRate?}`。
- 按键任务使用预合成缓存，入队即可播；结果任务在轮到它时才同步合成（若之前被丢弃，就省掉合成）。
- **新按键**：丢掉尚未开口的旧结果（人已往下输入）；如果正在播结果，停止它；不丢未播完的按键。
- **新结果**：替换尚未开口的旧结果；不打断按键。
- **关闭某开关**：移除该类型排队任务；正在播的就停止。
- 同一时间只播一条；`onended` 或“时长 + 3s”兜底后播下一条。
- 播放前峰值归一化到 0.9，并裁掉首尾静音（约 10ms 余量、5ms 淡入淡出），避免按键拖尾和爆音。

### 3.5 加载与缓存

- **首次开启某个开关**（用户手势）立即开始加载；显示进度。整个 96MB 只下载一次。
- **刷新后开关仍开**：页面加载约 600ms 后后台自动加载（已缓存时几乎瞬时），不阻塞计算。
- 加载顺序：注入 3 个脚本 → 初始化 wasm 工厂 → 4 个模型文件流式下载并写入 MEMFS → 创建 TTS → 预合成 19 句固定短语（17 个按键词 + 2 句开启提示）→ 就绪。
- 引擎常驻内存；关闭两个开关不卸载（避免再次 96MB/3s 的准备）。
- 合成结果按文本缓存，最多 20 条（与 /ws/voice 一致）。
- 加载失败保留用户的开关状态，状态行显示原因和「重试」；不静默失败。

### 3.6 默认值与保存

| 设置 | 默认 | 存储 |
| --- | --- | --- |
| 按键播报 | 关 | `voiceKeys: boolean` |
| 结果播报 | 关 | `voiceResult: boolean` |

- 与现有设置同存 `localStorage` 键 `cal-phone.settings.v1`；沿用 try/catch，存不了就只在本页生效。
- 重置（「运算类型」）不清空语音设置。

- 来源：`/ws/voice/public/`（已验证的 1.13.5 运行时）+ `https://huggingface.co/csukuangfj/matcha-icefall-zh-baker`。
- 仓库不提交 96MB 二进制；`voice/` 加入 `.gitignore`。
- 新增 `scripts/voice-assets.sha256`（7 个文件的固定哈希，随 git 提交）和 `scripts/install-voice-assets.sh`：
  - 默认从 `VOICE_SRC=/ws/voice/public` 复制到 `voice/`；
  - `sha256sum -c` 校验，防止版本/模型混淆；
  - 源缺失时打印 HF 链接与手动步骤。
- 新增 `scripts/voice-server.mjs`：本地静态服务器（默认 4174），设置 `.wasm`/`.onnx` MIME，供手动试听与 `tests/voice` 使用。TTS 不需要 COOP/COEP，普通 HTTP 即可。

### 4.2 `index.html` 内的改动

保持单文件业务代码，只新增一段语音模块（IIFE 内）：

1. 常量与状态：`VOICE_BASE = "voice/"`、`voiceState = idle|loading|preparing|ready|error`、进度、引擎 Promise、音频缓存、播放队列。
2. `loadVoiceEngine()`：从 /ws/voice 的 `loadSherpaTts` 改写而来：
   - 脚本已存在（测试注入）则跳过注入；
   - `locateFile` 指向 `voice/sherpa-onnx-wasm-web.wasm`；
   - 模型文件用 `Content-Length` 预分配，流式读取，进度回调；
   - `createOfflineTts` 使用 Matcha 配置（`numThreads:1`、`cpu`、`noiseScale:0.667`、`lengthScale:1.0`）；
   - 校验 `tts.handle`。
3. `preparePhrases()`：预合成 19 句，逐句 `yield` 给事件循环，更新“8/17”状态；单句失败只记日志，该键走按需合成兜底。
4. `announce(kind, text)`：开关判断、任务入队、写观测属性。
5. `pump()` / `playSamples()`：串行合成与播放，`AudioContext` 在首次用户手势时创建并 `resume()`。
6. `numberToChineseReading()`：从 `/ws/voice/src/numbers.js` 移植（~110 行），保留原注释与来源说明。
7. 动作函数返回“是否真的发生”，供播报判断：
   - `appendCharacter`、`deleteLastCharacter` 返回 boolean；
   - `commitInput({announceCommit})`：手动确认/自动确认传 true，`calculate()` 内部提交传 false；
   - `chooseOperator` 在点击处播报运算符；
   - `calculate()` 成功/除零时播结果。

### 4.3 设置面板与主界面

- 回滚：语音是增量功能；旧 `index.html` 不引用 `voice/`，残留文件无害。

## 5. 方案与取舍

引擎：**已由需求固定为 sherpa-onnx WASM + Matcha-TTS**，不再比较浏览器 `speechSynthesis`、云 TTS 或录音。浏览器语音只作为“已知失败时的可能后备”，本版不实现（见 §9 待拍板）。

按键音频：

- **A（已选）预合成缓存**：加载完成后一次性合成 19 句，按键 0 延迟；代价是首次准备约 3s。
- B 每次按键即时合成：省 3s 准备，但每键 150–250ms 延迟 + 主线程卡顿，连续录入会明显拖沓。
- C 预录音频文件：音色统一，但 96MB 已很重，再带 base64/文件不现实。

加载时机：

- **A（已选）开启时加载 + 刷新后后台加载**：用户明确开过，且 HTTP 缓存后几乎瞬时；主界面有“语音准备中”提示。
- B 只在打开设置面板时加载：省流量，但用户开完面板去录入时仍是静音。
- C 页面加载即加载：开关关着也下 96MB，不可接受。

资源位置：

- **A（已选）自包含 `voice/`**：`index.html` 旁一个目录，部署/回滚都简单，不耦合 `/ws/voice` 站点。
- B 复用 `/var/www/hotword-asr-lab` 的静态目录：省一份磁盘，但两个站点互相牵连，回滚会互相影响。

队列：

- **A（已选）自维护串行队列**：能只丢弃旧结果、保留按键，能处理打断。
- B 依赖引擎/`AudioContext` 自然排队：无法选择性丢弃，结果会把按键顶掉或反过来。
- C 每键停止上一条：连按会吞字，与“确认没按漏”冲突。

## 6. 非目标

- 不做语速/音量/音色选择；Matcha 只有单说话人。
- 不播整个算式、不播按键累积输入、不播编辑输入框里的直接打字。
- 不做浏览器语音后备、不做云 TTS、不做录音资源（除非 §9 拍板加后备）。
- 不改计算、历史、编辑、自动确认、基数的语义。
- 不做多语言（固定中文）。
- 不把 96MB 资源提交进 git，不做首次使用前的预下载提示弹窗（开关本身就是确认）。

## 7. 反目标（做到了也算失败）

- 开关打开却没有任何声音，也没有状态说明（加载中/失败必须可见）。
- 开关关闭时仍出声。
- 快速连按漏念数字；结果语音把未念完的按键顶掉；两条结果叠在一起。
- 开启后主界面卡死超过 1 秒（按键预合成必须分片让出主线程）。
- 刷新后开关丢失，或开关不计入「已自定义」。
- 每次刷新重新下载 96MB（缓存头必须 immutable）。
- 320px 下设置面板横向溢出，或控件小于 44px。
- 语音失败影响计算、历史、编辑或除零恢复。

## 8. 约束与风险

- **手机内存/兼容性**：/ws/voice 只在桌面 Chromium 验证；73MiB 模型 + 15MB wasm + MEMFS 在手机上可能吃紧。必须真机实测（目标手机 + 8444），失败时应用显示错误与重试，不能白屏或崩溃。
- **主线程合成**：结果句 0.3–0.5s 同步阻塞；按键已预合成，不受影响。后台标签页可能暂停音频，不保证后台播报。
- **首次加载**：局域网 + 解析 + 预合成约 10–30s（视设备），状态与进度必须一直在。
- **iOS**：`AudioContext` 需用户手势；首次开启/按键时解锁。静音拨片会让播报没声。
- **许可**：模型仅限非商用；设置面板与 README 都注明。
- **缓存**：依赖 `immutable` 长缓存；清缓存后重新下载 96MB。
- **大数/科学计数**：`String(1e21)` 这类结果无法转中文读法时，本次不播（不念错），列入已知限制。

## 9. 验收

### 9.1 自动化（无声环境）

新增 `tests/voice/`（普通 HTTP，静态服务器 + Playwright）：

1. **设置与持久化**：默认关；开启后刷新仍在；`已自定义` 出现；`file://` 下开关禁用。
2. **按键播报**：注入假引擎（`window.SherpaOnnx` / `createOfflineTts`），依次按 9、5、`.`、退格、确认、`+`，`data-speech-log` 为 `九/五/点/退格/确认/加`；重复小数点、空确认、空退格无记录；`=` 不产生按键记录。
3. **结果播报**：`9.5 + 9.2 =` → `结果 十八点七`；负数 → `负`；除零 → `不能除以零`；自动等号也播。
4. **独立开关**：只开结果时按键静音；只开按键时结果静音。
5. **排队/打断**：快速 1、2、3 全部入队且顺序正确；结果排在按键之后；结果未播完时按新数字，旧结果从播放日志消失、按键照播；关闭开关清掉该类型排队。
6. **布局**：320×568 / 390×844，新增两行 + 状态行 + 进度条无横向溢出，开关可点。
7. **回归**：`cd tests && node suite.mjs` 现有 18 场景 / 206 检查全绿（`file://` 不加载语音资源）。

### 9.2 真实引擎 smoke（可选，手动/CI 慢测）

`VOICE_REAL=1 node tests/voice/run.mjs --real`（需要 `voice/` 已安装）：

- 加载真实模型，等待 `data-voice-state=ready`；
- 按 9、5、`=`，断言 `data-speech-played` 含 `九/五/结果 九十五`，`data-speech-last-ms > 100`；
- 断言所有 19 句预合成成功、时长 > 0、无静音。

### 9.3 真机人工验收（必须）

1. 手机打开 `https://192.168.1.25:8444/`，设置里开启按键播报，等待“语音已就绪”。
2. 连续按 10 个数字：每个都念、顺序正确、不吞字；按点、退格、确认、加减乘除都有声。
