# 统分设置：自动回车 + 基数

- 日期：2026-11-19
- 状态：待批准
- 范围：`index.html`（单文件计算器）与 `tests/`（Playwright 场景）
- 规模：小改动，但跨「设置 / 计算 / 历史 / 编辑 / 测试」五处

## 1. 为什么做

这个计算器现在用于**统分**：一份成绩由若干笔分组成，每笔都要点一次“回车”确认，再按“=”求值。两个摩擦点：

1. 每笔分都要伸手点“回车”，连续录入时很碎。
2. 很多统分有“基础分”，每份成绩都要先加同一个数，现在只能把它当普通一笔分重复输入。

目标：在右上角加一个设置入口，设置 **t 秒后自动确认当前数字**，以及一个 **基数**（基础分），让一份成绩可以“输数字 → 停一下 → 输下一笔 → =”。

## 2. 已定的行为

### 2.1 设置入口

- 齿轮按钮固定在页面右上角（`app-header` 右侧），44×44 可点区域，颜色压低（约 60% 不透明度）但**始终可见、可点**；不做“过几秒自动隐藏、只留隐形热区”，因为统分时用户需要随时改 t 和基数。
- 点击后从齿轮下方弹出小面板（原生 `<dialog>` + `showModal()`，背后有淡遮罩），右侧与齿轮对齐，宽度 `min(320px, calc(100vw - 16px))`；点遮罩、按 Esc、点“完成”都关闭。
- 打开时焦点进入面板第一个控件，关闭后焦点回到齿轮；`aria-expanded`、`aria-haspopup="dialog"` 同步。
- 当 t 或基数处于非默认状态时，齿轮右上角显示一个 6px 琥珀色小点，提示“有设置生效”。

### 2.2 自动回车

- 菜单里 t 的档位：**0（关闭）、0.5、1、1.5、2 … 10 秒**，每 0.5 秒一档；**默认 0（关闭）**，设过一次后记住。
- 开启后，主输入框每变化一次（数字、小数点、退格、换运算符）就重新计时；停手 t 秒且输入框非空，自动执行现有的“回车”逻辑（`commitInput()`，把当前数字放进算式），**不会自动按“=”求值**。
- 以下情况不自动确认，也不显示进度：
  - 输入框为空；
  - 输入以 `.` 结尾（如 `9.`，避免 0.5 秒档把小数拆成 9 和 5；等下一个数字再计时）；
  - 设置面板打开期间（关闭后若输入框非空，重新完整计时 t 秒）；
  - t = 0。
- 可见反馈：
  - 输入框下沿一条 2px 琥珀色细进度条，t 秒走满即确认；任何输入都会让它从头再来。进度条绝对定位，不改变布局高度。
  - 确认后状态行短暂显示“已自动确认 9.5；继续输入或按 =”（复用现有 `aria-live` 状态行）；手动回车不显示这条提示。
  - 尊重 `prefers-reduced-motion`：不做进度动画，但自动确认照常工作，确认消息仍然播报。
- 手动“回车”、按“=”、重置、进入编辑、取消编辑、打开设置时，清除计时。

### 2.3 基数

- 菜单里一个“启用基数”开关 + 一个数字输入（允许小数与负数），默认关闭；关闭时输入禁用。
- 启用后，基数作为**每次计算的第一笔数**，与当前运算符从左到右折叠；按“=”后不沿用上一次结果，下一次计算仍从基数开始。
- 例：
  - 基数 10、`+`、9.5、9.2、9.0 → `10 + 9.5 + 9.2 + 9.0 = 37.7`
  - 基数关闭 → `9.5 + 9.2 + 9.0 = 27.7`
  - 基数 100、`/`、4 → `100 / 4 = 25`
  - 基数 0、`*`、5 → `0 * 5 = 0`（0 也是合法基数）
- 算式与历史都显示基数，结果不会看起来凭空多出来；历史条目保存**当时**的基数快照。
- 改基数只影响之后的新计算；编辑旧历史时用它自己的基数重算，不受当前设置影响。
- 编辑草稿顶部显示一个不可删除的“基数 10”标记，避免用户以为基数在操作数里可以改。
- 输入过程中改基数，当前未完成的算式立即按新基数重绘。
- 运算符还没选时，算式不拼基数（否则会出现 `10 9.5` 这种无运算符文本）；选中运算符后立即显示。选中运算符时的状态行带上基数，例如“已选择 +，基数 10，请输入数字”。
- 基数不参与“除以零”检查：它永远是第一笔数，不会成为除数；除数仍只可能是已输入的操作数。
- 历史编辑的求值仍用 float64 从左到右折叠，不引入表达式解析器。

### 2.4 退格撤回

- 输入框有内容时，“退格”仍只删一个字符。
- 输入框为空且处于 `input` 或 `edit` 态、已有确认过的数字时，“退格”**撤回最后一笔已确认的数**，并提示“已撤回 9.2；继续输入或按 =”。
- 连续按就一笔一笔往回撤；撤回只影响操作数，不影响基数。
- `result` / `error` 态不撤回（已完成记录请用历史里的“编辑”），保持现状。
- 编辑操作数输入框时，退格仍由该输入框自己处理，不触发主输入框的撤回。

### 2.5 默认值与保存

| 设置 | 默认 | 范围 |
| --- | --- | --- |
| 自动回车 t | 0（关闭） | 0、0.5、1 … 10 秒 |
| 启用基数 | 关 | 开 / 关 |
| 基数值 | 0 | 有限小数或负数 |

- 设置存 `localStorage`（键 `cal-phone.settings.v1`），刷新后保留；读写包在 try/catch 里，存不了就只在本页生效。
- 历史仍**只存在当前页面**，不持久化，和现在一致。
- 重置（“运算类型”按钮）不清空设置。

## 3. 非目标

- 不做平均分、去掉最高/最低分、名次等统计功能。
- 不做历史持久化、账号、云同步。
- 不在“=”前编辑中间某笔分；只提供“退格撤回最后一笔”。
- 不新增负号键，不新增表达式解析，不改变持续沿用运算符的语义。
- 不自动按“=”，不自动滚动、不自动复制结果。
- 不把设置做成每次刷新都重置的临时值。

## 4. 反目标（做到了也算失败）

- 自动确认没有任何可见反馈，用户不知道数字何时被收走。
- 自动确认在设置面板打开时、或在小数点后半个数（`9.`）时触发。
- 改基数让旧历史的结果跟着变。
- 为了自动回车而改变手动回车/等号的现有行为。
- 320px 宽度下菜单或进度条造成横向溢出；控件小于 44px 或字号小于 16px。

## 5. 方案与取舍

设置入口：

- **A（已选）齿轮下方弹出小浮层 + 遮罩**：符合“从右上角弹出”，统分算式和键盘仍可见，320px 下可容纳。代价是需要自己做锚定定位和焦点管理。
- B 全屏/底部对话框：实现最稳，但盖住正在统的分，弹出手感弱。
- C 页面内展开：最省事，但把键盘往下推，不是“弹出”。

自动回车的可见性：

- **A（已选）输入框下沿进度条 + 确认提示**：统分时能判断还剩多久，减少“怎么还没收”的疑惑。
- B 静默确认：界面更干净，但自动收数字不可预期。

## 6. 约束

- 保持单文件、自包含、无外部依赖；不引入框架或构建步骤。
- 沿用现有状态机（`select / input / result / error / edit`）、float64 从左到右折叠、44×44 触控、≥16px 输入字号。
- 320×568 与 390×844 下无横向溢出（包括菜单打开、基数标记出现时）。
- 现有 `tests/suite.mjs` 必须继续通过；新增场景覆盖本设计。`tests/README.md` 已注明：当前产品数字键默认可用，而 `cold-start.keys-disabled` 是 HEAD 上就存在的过期断言，本次实现时一并更新到当前产品（或明确标注为既有失败，不混入本次验收）。

## 7. 验收场景

1. **设置开合**：齿轮可见且 ≥44px；点击弹面板；Esc/遮罩/完成关闭；焦点回到齿轮；无 pageerror。
2. **设置保存**：t=1、基数 10 开启，刷新后仍在，并参与下一份计算。
3. **自动回车**：t=0.5 时输入 `9.5`，约 0.8 秒后数字进算式、输入框清空、状态行提示；输入过程中计时重置（9 → 停 0.3 秒 → 5，最后得到 95 而不是 9 + 5）；`9.` 结尾不确认；t=0 不确认；设置面板打开时暂停。
4. **基数计算**：基数 10 + 9.5 + 9.2 + 9.0 = 37.7；关闭基数 = 27.7；基数 100 / 4 = 25；基数 0 * 5 = 0；显示算式与历史；改基数不影响旧历史；编辑旧历史用它自己的基数重算。
5. **退格撤回**：两笔已确认后连续退格逐笔撤回并提示；撤回不删基数；`result` 态不撤回；编辑态撤回草稿最后一笔。
6. **布局**：320×568 与 390×844，菜单打开、进度条显示、基数标记出现时均无溢出，控件尺寸/字号达标。
7. **确定性**：两个全新 context 执行相同设置与录入序列，历史一致。

## 8. 留给实现者的决定

- 齿轮图标的具体 SVG 路径、进度条动画实现（`Element.animate` 或 CSS 动画）、提示文案的最终措辞。
- 设置面板里 t 用原生 `<select>`（0–10，0.5 步进）还是加减步进器；倾向于原生 `<select>`，移动端不弹键盘、值一定合法。
- 基数输入的即时校验细节：非法输入不改变已生效基数，失焦时归一到合法值。
- 页面切到后台导致计时被节流时，回到前台是否重新计时（倾向：若输入框非空，重新完整计时）。
- 新测试文件的拆分方式与选择器命名（建议 `settings / auto-confirm / base / undo` 四个场景文件）。
