# 测试用例总表

本文件是**全量清单**：三套件、每个用例的功能 / 步骤 / 预期结果。
机器可执行的源头仍是代码；本表用来回答「到底测了什么、哪条没测」。

## 总览

| 套件 | 入口 | 规模 | 运行命令 | 当前状态 |
| --- | --- | --- | --- | --- |
| A 共享回归套件 | `tests/suite.mjs` | 43 场景 / 673 检查 | `cd tests && node suite.mjs` | ✅ 全绿（连跑两次） |
| B 功能级驱动 | `.agents/skills/verify-calculator/scripts/drive.mjs` | 12 场景 / 81 用例 | `bash .agents/skills/verify-calculator/scripts/launch.sh` 后 `node .../drive.mjs --scenario <名>` | 需本地服务器；断言与截图证据见 `feature/runs/` |
| C 语音套件 | `tests/voice/run.mjs` | 8 组 / 75 检查 | `node tests/voice/run.mjs` | ✅ 全绿 |

## 本轮修复（语音套件 3 条红项）

`node tests/voice/run.mjs` 之前 63/66，三条失败同源，已修：

- **根因**：产品新增了「结果后暂停输入」（`resultPause`，默认 1 秒）。语音套件在 `=` 之后立刻点数字，用来验证「继续输入时结果不播报」，但数字被暂停吞掉，于是结果照常播报、第 4 个按键也没进队列。
- **修复**：`tests/voice/run.mjs` 的 `openPage` 在被 seed 设置的上下文里补 `resultPause: 0`，并注释说明暂停本身由 A 套件的 `settings-pause` 覆盖；未 seed 的上下文保持默认，用于断言原始设置态。
- **断言未改弱**：`queue.quick-no-result` / `queue.quick-keys` 的期望值原样保留，现在真正被执行到。

## 明确不在范围内

- 刷新后保留历史：历史按设计只存在内存。
- 跨浏览器一致性：只在 Chromium（Playwright）验证。
- 任意精度小数：float64 是契约，`1 / 3` 的展示就是 `0.3333333333333333`。
- 存储结构版本迁移：坏数据已覆盖（A 套件），但没有「旧结构升级到新结构」的用例。
- 动画逐帧效果：只断言 `data-active` 与几何尺寸。
